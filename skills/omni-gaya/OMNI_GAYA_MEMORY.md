## ⚠️ GOTCHAS — chronicled lessons (dated; what bit us, what to do instead)
- **Don't trust inherited memory as fact.** EDIDTH's memory logged ~10 "shipped" deliverables that never existed on disk (verified 2026-05-27). When absorbing another agent's state, treat its claims as unverified until a file check confirms. Grill-Me earned its seat here.
- **EDIDTH inventory pass is MANDATORY before any bulk file move.** On 2026-06-03 I archived a "nested duplicate" folder without inventorying it; the Python voice Gaya (352MB venv) got swept up. Restorable, but a slip. Inventory > assume. EDIDTH now gates this in v6.0.
- **Headless Chrome clamps its window to ~500px minimum width.** `--window-size=375,780` silently lays out at **vw=500** and then crops the screenshot to 375 — text looks "clipped" and you will chase a CSS bug that does not exist (burned real time 2026-07-09). `--force-device-scale-factor` does NOT shrink the CSS viewport either. To test narrow layouts: **measure, don't screenshot** — dump `documentElement.scrollWidth > innerWidth` via `--dump-dom`, or force `html{width:375px}` (but remember viewport media queries then still match the real width, so media-query-dependent rules won't reflect mobile).
- **Infinite `requestAnimationFrame` loops stall `--print-to-pdf`.** Virtual time never goes idle, so Chrome hangs forever (no PDF, no error). Fix: render the PDF with `--force-prefers-reduced-motion` so the single-draw path runs and rAF loops never start. Screenshots are unaffected (they fire at budget expiry). Also: always bound the wait with `WaitForExit(ms)` + `Kill()`, never a bare `-Wait`.
- **`--screenshot` ignores runtime scroll.** `window.scrollTo()` before capture does nothing (and `scroll-behavior:smooth` freezes under virtual time anyway). To capture a lower section, inject `body{margin-top:-Npx}` into a temp copy.
- **Curving flat modules = faceted arc, not a smooth bend.** On the LED Wall Planner (2026-06-25) two curve models shipped and both scattered the cabinets: (1) vertices-over-`cols-1` + chord radius, (2) centres-on-arc + arc-length radius `wW/A`. Both only hold for many columns + small angle; few columns + big angle exposes them. Correct model is **chord-vertex** (each panel a chord, chord-solved radius `cW/(2·sin(Δθ/2))`, placed at chord midpoints, sharing corner vertices). Now codified in the `curved-led-wall` skill — use it, don't re-derive.
